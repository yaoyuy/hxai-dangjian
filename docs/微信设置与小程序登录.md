# 微信设置与小程序登录（方案 A）

这份文档讲三件事：**微信参数放在哪、怎么在后台填、登录怎么走**。
第一阶段用个人订阅号 **HXAI云** 测试，所以下面每一条都区分「现在能做的」和「要等学校认证号的」。

---

## 1. 为什么微信参数要改成存在数据库里

原来的做法是把 `WECHAT_APPID` / `WECHAT_APPSECRET` 放在 `.env`。两个问题：

1. 本机的 `.env` 受安全策略保护（`secret.basename.env`），**程序自己改不了**，必须用户手工编辑；
2. 第二阶段要换成学校的公众号 / 小程序，AppID、AppSecret、Token 全都不一样，改 `.env` 就要动服务器上的文件。

现在改成：**参数存在数据库表 `sys_setting` 里，后台「微信设置」页填写，保存即生效**。
不用改代码、不用改 `.env`、不用重启。

取值优先级（`backend/settings_store.py`）：

```
后台「微信设置」页填写值（数据库）  >  .env 里的同名配置  >  代码里的默认值
```

> 密钥（AppSecret、EncodingAESKey）在页面上**只显示脱敏值**（例如 `secr****56`），
> 不回填明文；**密文输入框留空 = 保持原来的值不变**（想清空就先换掉整个参数）。
> 这就是为什么页面上写着「留空表示不修改」。

## 2. 后台「微信设置」页怎么用

地址：`http://127.0.0.1:5000/admin/wechat`（需要管理员登录），
或在后台顶部导航点「微信」。

页面上有 6 个区域：

| 区域 | 填什么 | 从哪拿 |
|---|---|---|
| 公众号（订阅号 / 服务号） | 公众号 AppID、AppSecret、服务器配置 Token、EncodingAESKey | 公众平台「设置与开发 → 基本配置」拿 AppID/AppSecret；「设置与开发 → 基本配置 → 服务器配置」拿 Token 与 EncodingAESKey |
| 小程序 | 小程序 AppID、AppSecret | 微信公众平台小程序后台「开发管理 → 开发设置」 |
| 登录方式与白名单 | 登录方式（`test` / `both` / `wechat`）、是否启用白名单、网页授权 scope | 见下面第 3 节 |
| 首页公告 | 想在首页顶部显示的公告文字 | 可留空 |
| 服务器地址 | 自动算出：公网地址、`/wechat` 回调地址、网页授权回调地址、网页授权跳转链接 | 地址来自 `PUBLIC_BASE_URL`（没填时自动读项目根 `.tunnel_url`） |
| 连接测试与菜单推送 | 「测试公众号 / 小程序参数」「用接口推送自定义菜单」两个按钮 | 会真的请求微信接口，把返回的原始错误显示出来 |

**关于那两个按钮，如实说明：**

- 「测试参数」会调微信接口拿 `access_token`。个人订阅号也能拿到 token，但**没有菜单权限**；
- 「推送菜单」会调 `menu/create`，个人订阅号必定返回 **`48001 api unauthorized`**。
  页面会把 48001 原样显示，并写明「这是微信权限限制，不是代码问题」，
  **不会伪装成推送成功**。菜单目前是在公众平台后台手工建的（见 `docs/公众号菜单与公网访问说明.md`）。

## 3. 三种登录方式

后台「登录方式」三个选项，对应前台登录页完全不同的样子：

| 值 | 含义 | 登录页显示 |
|---|---|---|
| `test`（默认） | 只允许本地测试账号 | 账号密码表单 + 蓝色提示「测试登录，非微信身份」 |
| `both` | 测试账号 + 微信登录都可以 | 两个入口都有 |
| `wechat` | 只允许微信登录 | 隐藏测试表单，只显示微信入口（**没配好参数时会谁都进不去，慎用**） |

不管选哪个，**只要是用本地账号登录，页面和接口都会写明「测试登录，非微信身份」、
`has_openid=false`，不会假装已经拿到微信 openid**。
只有真的通过微信 `jscode2session` / 网页授权拿到 openid 时，才显示「微信身份（已获取 openid）」。

## 4. 微信登录白名单

个人号拿不到 openid，但小程序能拿到。拿到 openid 之后要有人管——这就是白名单。

**用途**：禁止「任何人打开链接就自动注册成党员」。只有白名单里的微信才能登录系统。

后台地址：`http://127.0.0.1:5000/admin/whitelist`

两种录入方式：

1. **先填姓名和手机号，openid 留空**：等这个人第一次用微信登录时，系统自动把 openid 补到这一条上
   （按手机号/绑定账号匹配），不用你去问他 openid 是多少；
2. **已经拿到 openid 就手工填**：openid 一列填进去，并可以顺手绑定到已存在的系统账号。

其他操作：每一行可以改手机号/角色、**停用**（停用后该微信立即被拒，返回 `whitelist_disabled`）、删除。
白名单开关在「微信设置」页（`whitelist_enabled`）——**关掉它的意思是任何微信都能自动建号**，
生产环境不要关。

演示数据里已经按 5 个测试党员建好了白名单（openid 留空），可以直接拿来试。

## 5. 小程序 openid 登录：真实链路

**这是个人号唯一能拿到真实 openid 的正路**（个人订阅号没有网页授权）。

```
小程序里 wx.login()  →  拿到临时 code
      ↓  （POST /api/auth/wechat-login  {"type":"wxapp","code":"..."}）
服务端 GET https://api.weixin.qq.com/sns/jscode2session?appid=..&secret=..&js_code=..&grant_type=authorization_code
      ↓  返回 {"openid": "...", "session_key": "..."}
服务端 _resolve_openid_user(openid)：白名单校验 → 已绑定账号 → 手机号匹配 → 新建账号
      ↓
写入 Flask session，前台 /me 显示「微信身份（已获取 openid）」
```

对应代码：`backend/wechat.py:jscode2session()`、`backend/api/auth_api.py:wechat_login()`。

**要真的跑通这条链路，需要（个人就能办，但都要时间）：**

1. 用个人身份证注册一个**小程序**（个人主体可以）；
2. 小程序后台拿到 AppID / AppSecret，填到后台「微信设置 → 小程序」；
3. 小程序**自身要 ICP 备案**（2023-09 起强制，个人主体可备案，约 1–2 周）；
4. 后端要有一个**已备案的 HTTPS 域名**填进小程序「服务器域名」白名单
   （IP、带端口、未备案域名都不行——这是第二阶段学校域名要解决的）；
5. 小程序前端页面要用 WXML/WXSS 重写（**后端 6 个 API 模块不用改**，它们已经是纯 JSON 接口）。

> 本项目**没有**附带小程序前端——因为第 3、4 条依赖备案域名，本地跑不起来。
> 第二阶段学校给域名后，可以照着现有 7 个页面写小程序前端，后端接口直接复用。

## 6. 本地怎么联调（不接真实微信）

没有小程序也能先验证「openid → 用户 → 登录」这段逻辑，用**开发联调 openid**：

1. 后台「微信设置」→ 登录方式改成 `both` → 保存；
2. 打开 `/login`，展开「开发联调：手工提供 openid（非真实微信授权）」；
3. 填一个 openid（例如 `dev_openid_test_001`）→ 提交。

会发生什么：

- 这个 openid 不在白名单 → 返回 **403 `not_in_whitelist`**，提示「请联系支部管理员把你的 openid 加入白名单」；
- 先去后台白名单加上它 → 再登录 → 成功，系统新建账号（账号名形如 `wx_xxxx`）；
- 返回体和页面上都写着 **「本地联调登录（openid 由开发者手工提供，非真实微信授权）」**；
- 只有 `test` / `both` 模式下才允许这个入口；`wechat` 模式下被拒绝。

另外还有 `POST /api/auth/bind-openid`：先用测试账号登录，再把 openid 绑到自己账号上
（重复绑定同一个 openid 返回 409）。它只用于联调，第二阶段拿到真实 openid 后同样可用。

**注意**：`dev_openid` 联调**不会**让页面显示成微信身份——它明确标注是手工提供的 openid。

## 7. 如实边界（不要被误以为已经做完）

| 说清楚的点 | 事实 |
|---|---|
| 个人订阅号的网页授权 | **没有**。`oauth_access_token` / `oauth_userinfo` 代码写好了，但个人号调用会返回 `api unauthorized`；`/login` 页面上也如实写着这句话 |
| 个人订阅号的自定义菜单 API | **没有**。推菜单返回 48001，页面原样显示 |
| 现在的 openid 来源 | 只有 ①小程序 `jscode2session`、②公众号网页授权（要认证） 、③开发联调手工填。**第一条路现在就能走通，但需要先注册小程序** |
| 登录页在 `test` 模式下 | 一律标注「测试登录，非微信身份」 |
| 微信参数 | 现在**是空的**（`未配置`），后台「微信设置」页如实显示未配置状态，直到你填入真实 AppID |

## 8. 第二阶段要改的东西

| 要做的 | 改哪里 | 说明 |
|---|---|---|
| 换成学校公众号 | 后台「微信设置 → 公众号」填学校 AppID / AppSecret / Token / AESKey | 不用改代码、不用改 `.env` |
| 启用服务器配置（消息回调） | 公众平台填 `https://<学校域名>/wechat` + 同一套 Token | 代码里的 `/wechat` 验签与被动回复已实现；**启用后后台手工设的菜单会自动失效**，要改用 `POST /api/wechat/menu/push` 推菜单 |
| 网页授权拿 openid | 公众平台配置「网页授权域名」（学校事业单位主体 + 已备案域名 + 上传校验文件） | 配置后登录方式可改 `wechat`，回调地址就是页面上的 `/login?mode=wechat` |
| 菜单直达网页 | 认证订阅号/服务号 + 已备案域名 | 认证后菜单才能填外链，`/api/wechat/menu/push` 会推「跳转网页」菜单 |
| 小程序 | 学校小程序 AppID / AppSecret 填「微信设置 → 小程序」 | 服务器域名白名单填学校 HTTPS 域名 |
