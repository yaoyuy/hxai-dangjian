# 小程序开发与发布说明（第一阶段：个人号测试）

> 目的：把公众号菜单做成「点一下直接进系统」。个人未认证订阅号做不到（微信限制），
> **小程序是唯一现实路径**。本文说明整条链路、每步要什么材料、以及学校在第二阶段要提供什么。
>
> 现状（2026-10-25）：本项目的小程序前端代码已写好，位于 `miniprogram/`；
> 但**还没有注册小程序**，所以公众号菜单暂时仍是「发送消息 → 文字 + 网址」。

---

## 一、为什么必须走小程序

| 菜单类型 | 个人未认证订阅号 | 说明 |
| --- | --- | --- |
| 跳转网页 | ❌ | 保存时必报「发布失败，链接内容不属于当前公众号」。微信要求链接内容属于本号或本号已配置的域名，而未认证个人号无法配置网页授权域名 / 业务域名 |
| 跳转小程序 | ✅（选项可用） | 但必须先**注册一个小程序并关联到公众号**。当前后台点「选择小程序」提示「暂无关联的小程序，请在“小程序-小程序管理”内进行关联」 |
| 发送消息（文字） | ✅ | 现在的临时方案：点菜单 → 回一条带网址的文字 → 再点网址（两次点击） |

结论：个人号想「一次点击进系统」，只能做小程序。

## 二、整条链路（6 步）

```
① 注册小程序（个人主体，免费，约 10 分钟）
        ↓
② 完善小程序信息 + 选服务类目（要过审核）
        ↓
③ 小程序备案（2023-09-04 起强制，免费，1~5 工作日）
        ↓
④ 开发（本项目 miniprogram/ 目录，微信开发者工具）
        ↓
⑤ 发布（提交审核 → 审核通过 → 发布上线）
        ↓
⑥ 公众号后台关联小程序 → 自定义菜单「跳转小程序」
```

### ① 注册小程序
- 入口：微信公众平台 <https://mp.weixin.qq.com/cgi-bin/wx> → 「前往注册」，或 <https://mp.weixin.qq.com/wxopen/waregister>
- 需要：**一个没注册过公众平台的邮箱** + 身份证 + 微信扫码（管理员身份）
- 个人主体免费；企业/个体户主体需营业执照（第二阶段学校走事业单位主体）
- 完成后拿到 **AppID**（填到 `miniprogram/project.config.json` 的 `appid`）

### ② 完善信息 + 服务类目
- 名称可以与公众号不同（个人小程序名称唯一，被占用要换）
- 服务类目：**与党建/政务相关的内容，个人主体审核风险较高**，可能被驳回。
  第二阶段用学校（事业单位）主体注册会顺畅得多。

### ③ 备案
- 官方指引：<https://developers.weixin.qq.com/minigame/product/record/record_guidelines.html>
- 2023-09-04 起，新增（未上架）小程序必须先备案才能上架
- 个人可备案：身份证、人脸核验；**证件地址与备案省份不一致会被要求居住证**
- 时长约 1~5 个工作日，免费

### ④ 开发
- 用**微信开发者工具**打开本项目的 `miniprogram/` 目录
- 开发/体验阶段：开发者工具「详情 → 本地设置 → 勾选**不校验合法域名**」，即可直连
  `http://192.168.x.x:5000`（校园网内网地址，见 `miniprogram/config.js`）
- 正式版限制：`wx.request` 的服务器域名**必须是已 ICP 备案的 HTTPS 域名**（IP、带端口、未备案都不行）
- 个人主体小程序**不能用 web-view**（官方文档原文「个人类型的小程序暂不支持使用」），
  所以本项目的 7 个页面是**原生 WXML/WXSS/JS 重写**的，不是套壳 H5

### ⑤ 发布
- 开发者工具「上传」→ 公众平台「版本管理」→ 提交审核 → 通过后「发布」
- 审核会检查：类目是否匹配、有没有诱导分享/支付、内容是否合规

### ⑥ 关联 + 菜单跳转小程序
1. 公众号后台左侧「小程序管理」→「添加」→「关联小程序」
2. 用**公众号管理员微信扫码**验证身份（无门槛、免费）
3. 输入小程序 **AppID** 搜索 → 关联
4. 回到「互动管理 → 自定义菜单」，子菜单「消息类型」选**跳转小程序**
5. 选择刚关联的小程序，填**小程序路径**（如 `pages/study/study`）和**备用网页**
   - 备用网页只给极老版本微信兜底；**它是否同样受「链接内容不属于当前公众号」限制尚未验证**
     （等有了小程序才能实测；如果被拦，备用网页可以先填本号已发表的一篇图文）
6. 「保存并发布」→ 60 分钟内对所有用户生效

## 三、小程序怎么连后端

后端**一行不用改**——第一阶段已为小程序端准备好：

| 机制 | 位置 | 说明 |
| --- | --- | --- |
| 签名 token | `backend/auth.py` 的 `issue_token()` / `_user_from_token()` | 用 `SECRET_KEY` 签名，不落库；换 SECRET_KEY 即全部失效 |
| 取 token | `POST /api/auth/login`、`POST /api/auth/wechat-login` 返回 `data.token` | 小程序存到 storage |
| 带 token | 请求头 `X-Auth-Token`（也支持 `?token=`） | `backend/auth.py: current_user()` 先看 session 再看 token 头 |
| 微信身份 | `POST /api/auth/wechat-login {code}` → 后端 `jscode2session` 换 openid | 需要小程序 AppID/AppSecret（后台「微信设置」页填，存数据库） |
| 准入 | 白名单（后台「微信登录白名单」页） | openid 不在白名单 → 403，页面如实显示后端提示 |

小程序端地址配置在 `miniprogram/config.js`：

```js
module.exports = {
  // 开发/体验版：校园网内网地址（开发者工具需勾"不校验合法域名"）
  // 正式发布：必须换成已备案的 HTTPS 域名，例如 https://dangjian.example.edu.cn
  API_BASE: 'http://192.168.x.x:5000'
};
```

## 四、后端连哪台机器（三条路线，待用户选）

| 路线 | 成本 | 时间 | 特点 |
| --- | --- | --- | --- |
| **A. 体验版连本机**（当前电脑 + 校园网内网地址） | 0 元 | 立刻可用 | 只有连同一校园 WiFi 的手机能用；电脑要常开；正式版不能用（未备案 HTTP） |
| **B. 用户自己的云服务器 + 已备案域名** | 域名约 30~60 元/年 + 服务器（用户已有华为云） | 备案 1~2 周 | 体验版/正式版都能用；外网可访问；适合先跑起来 |
| **C. 微信云开发** | 按量计费 | 中等 | 要把 Flask 后端改成云函数/云托管，工作量大；是否要求小程序已认证待确认 |

> 注：免费匿名隧道（localhost.run / Cloudflare / serveo）已实测**不适合**——约 20 分钟换一次域名，
> 而菜单 60 分钟才生效，追不上（详见 `docs/公众号菜单与公网访问说明.md`）。

## 五、第二阶段（学校）需要提供什么

在小程序这件事上，学校要提供：

1. **主体类型**：用学校（事业单位）主体注册小程序，还是关联学校已有的小程序？
   - 若学校已有小程序：只需把本项目代码改造成它下面的一个分包/页面，或直接用它的 AppID 关联
   - 若新注册：需要学校出具**事业单位法人证书**、管理员身份信息、对公或管理员工微信扫码
2. **已备案域名 + HTTPS 证书**（小程序正式版 `wx.request` 的硬性要求）
3. **小程序备案**：由学校主体在微信后台完成（个人主体由我们做，学校主体需学校配合）
4. **服务类目**：学校主体可选的类目（如「政务民生 / 党建」相关），避免个人号被驳回
5. **公众号与小程序关联**：公众号管理员微信扫码 + 小程序 AppID
6. **是否使用学校现有公众号**：已认证服务号还能顺带解锁网页授权（openid）、JS-SDK、模板消息

> 这些与 `docs/部署与学校交接清单.md` 的第一阶段 P0/P1 清单是同一套，小程序部分额外需要第 1、4 两项。

## 六、已知风险与限制（如实）

1. 个人主体小程序的**服务类目审核**可能驳回党建类内容 → 这是最大不确定性
2. 个人小程序**不能用 web-view**，也不能用微信支付（本项目本来也不需要支付）
3. 未备案的 HTTP 内网地址**只能用于开发版/体验版**，正式版必须换成备案 HTTPS 域名
4. 小程序自身也要备案，未备案不得上架
5. 关联小程序与菜单改动都要**60 分钟**才对所有用户生效，调试时不要频繁发布
