## 0. 先说结论（一句话版）

**没有一个是「个人订阅号 + 点菜单直接进系统」的现成答案。** 12 个项目里，凡是能在微信里用的，靠的都是这两条路之一：

1. **已认证服务号 / 已认证订阅号**（要营业执照或事业单位主体 + 300 元/年微信认证 + 已备案域名 + HTTPS）；
2. **微信小程序**（要注册小程序主体 + 小程序备案，靠 `wx.login` 拿 openid，不依赖公众号菜单）。

**但它们的数据模型、表结构、微信 SDK 配置方式、后台可填微信参数这几件事，是能直接搬到我们这套 Flask 系统里的**——见第 4 节的「能用」清单。至于「整站搬过来直接用」，全部不行（语言栈、许可证、阉割版三个原因，见第 5 节）。

## 1. 调研方法（先说哪些路走得通，省得以后再踩）

| 通道 | 结果 |
|---|---|
| Gitee 官方搜索 API `/api/v5/search/repositories?q=党建` | ❌ 无 access_token 时返回空数组 `[]` |
| Gitee 网页搜索 `search.gitee.com`、`gitee.com/explore/topic/党建` | ❌ 抓取失败（status 0，反爬） |
| Bing 站内搜索 `site:gitee.com 党建` | ❌ 返回 26 字节空壳 |
| Gitee 单仓库 API `/api/v5/repos/<owner>/<repo>` 与 `git/trees?recursive=1` | ✅ **好用**，元信息 + 完整文件树都能拿到 |
| GitHub 搜索 API | ⚠️ 响应被截断到 50000 字符（每条目 ~10KB），`per_page>=5` 必然 JSON 解析失败。**技巧：`per_page=1&page=1..N` 按 star 降序逐条枚举** |
| web_search / anysearch（中文） | ✅ 能按名字查到仓库，但**搜不全**，只反复给同几个 |
| 关键词命中率极低的原因 | 「党建」二字在大量无关仓库的 README 里出现，搜索引擎排序被大 star 无关项目占据 |

## 3. 逐项目要点（带代码证据）

### 3.1 open-party（青海小怪兽，Gitee ⭐34 / GPL-3.0）——微信那套做得最"正规"，但门槛也最硬

- 目录：`admin/`（Vue3 + TS + Element Plus 后台）、`server/`（ThinkPHP6 后端）、`uniapp/`（会员端，一套代码出小程序 + H5 + App）。
- 微信 SDK：`server/composer.json` 依赖 `w7corp/easywechat ^6.8`。
- **网页授权链路（真代码）**：`uniapp/src/utils/wechat.ts` 的 `getWxCodeUrl()` 拼 `oauth2/authorize` 授权链接 → 回调带 `code` → 调 `OALogin({code})`；后端 `LoginLogic::oaLogin()` → `WeChatOaService::getOaResByCode($code)` 换 openid。
- **小程序链路**：`LoginLogic::mnpLogin()` → `WeChatMnpService::getMnpResByCode()`（jscode2session）。
- **决定性证据**（说明它也没绕过门槛）：`admin/src/views/channel/wx_oa/config.vue` 顶部提示原文「**温馨提示：填写微信公众号开发配置，请前往微信公众平台申请服务号并完成认证**」，同页要填服务器配置 URL + AppID/AppSecret。
- **对我们最有价值的一点**：微信 AppID/AppSecret/Token **不写在配置文件里，存在数据库、在后台页面里填**（`channel/wx_oa`）。我们正可以照这个改——顺便绕开本机 `.env` 被安全策略锁死、改不动的问题。
- 开源版功能只到「学习手册 / 党员风采 / 首页与个人中心装修」；**三会一课、活动报名、电子台账、数据看板一块都没有**（商业版 Java 才有）。

### 3.2 万岳党建（Gitee ⭐2616 / GPL-3.0）——star 最高，功能最少

- `zhihui.sdwanyue.com/`（PhalApi + ThinkCMF 5.1 双框架，PHP≥5.6 + MySQL + **Redis 必需**）、`uniapp/`（20 个页面）。
- **业务代码里没有任何微信身份获取**：全仓唯一 `jscode2session` 在框架 vendor 里（`vendor/thinkcmf/cmf-api/src/wxapp/controller/PublicController.php:64`），但 `app/` 下没有 wxapp 模块、安装 SQL 里也没有 `cmf_wxapp*` 表 → 死代码。自定义菜单 `cgi-bin/menu` 零命中。
- 真实登录 = 手机号 + 短信验证码（`Domain/Login.php userLogin()`，用户不存在自动注册）。**顺带发现两个安全隐患**：`Api/Login.php` 里「请先获取验证码」校验被注释掉；`Common/functions.php:57 sendCode()` 在开关关闭时直接返回 `msg='123456'` 万能码。
- 四块功能核查：三会一课只有 `SanhuiyikeModel` + 一个 H5 详情页（无计划/签到/记录）；「报名」全仓 0 命中；「台账」0 命中；「看板」只命中腾讯云 SDK 自带文件。
- 结论：它是「党建内容门户（CMS）」，不是党务管理系统。**可借鉴**：① 免注册自动开号 + 长效 token 落表；② API 层统一从 token 表/缓存解析 uid；③ 组织维度字段（partybranch/partypost）直接挂在用户与党员实体上；④ 一套 uniapp 多端 + H5 兜底跳小程序。

### 3.3 SmartPartyBuilding 智慧党建云平台（四川民图，GitHub ⭐9 前端 / LGPL-3.0）

- 后端 `gitee.com/scmt1/SmartPartyBuilding`（Gitee 上另有 `tq888` 的搬运副本 ⭐0）：Java **JDK11 + Spring Boot 2.4.5 + sofa-boot 微应用 + MyBatis-Plus + Redis + MySQL**。
- 前端拆成多工程：`dj-ui-dwgl`（党务管理）、`dj-ui-app`（手机端）、`dj-ui-go-view`（**数据大屏**）、`dj-ui-honor`、`dj-ui-lesson`、`dj-ui-message`、`dj-ui-tzgl`、`dj-fastcmscms`、`dj-portal`、`dj-survey`、`dj-xfzb`、`party-paas-all-in-one-online`（网关）。
- **微信相关代码（我们唯一见到的完整公众号+小程序 SDK 集成）**：`dj-server-dwgl/scaffold-facade/.../WxService.java`、`scaffold-server/.../common/bean/{WxApp,WxMiniApp,WxMp,WxPay}.java`、`config/{WxConfig,WxMpInRedisConfigStorage,WxMpServiceClusterImpl}.java` → 用 weixin-java-tools 那套（多公众号配置 + Redis 存 token），支持小程序、公众号、支付。
- 功能对照我们最相关的：**✅ 三会一课管理**（组织生活模块）、党员画像、党费缴纳、学习积分、投票问卷、**✅ 大数据分析大屏**、党建 AI 助手；移动端有我的支部/荣誉/积分/三会一课。
- 许可与商用：**LGPL-3.0**，README 要求「需标注"代码来源于四川民图科技开源项目"后即可免费自用运营」，禁止倒卖。
- **教训**：这是「功能最全的一个」，代价是 Java 微服务 + 网关 + Redis + 7 个前端工程——学校服务器上能跑，但和我们「Flask + SQLite、一个人维护」的定位不匹配。

### 3.4 2473-CI/PartyBuilding（GitHub ⭐33 / Apache-2.0）——**表结构最值得抄的一个**

- 目录：`BackEnd/`（SpringBoot + MyBatis）、`FrontEnd/`（Vue3 + Vite + Element-Plus）、`SQL/partybuilding.sql`、`需求规格说明书.doc`。
- **`SQL/partybuilding.sql`（21KB）里的 14 张表**，这正是「真实党务」的业务模型：
  `user`（用户）、`role`（角色）、`life`（组织生活/三会一课）、`activity`（活动）、`cost`（党费）、`study`（学习）、`test`（测验）、`examination`（考试）、`expand`（发展党员）、`transfer`（组织关系转接）、`commend`（表彰）、`help`（结对帮扶）、`volunteer`（志愿服务）、`Interview`（谈话）。
- **`openid` / 微信 / menu 在该 SQL 里 0 命中** → 它完全没有微信侧实现，纯账号密码登录。
- 许可证 Apache-2.0（可商用、可闭源改），比 GPL 系友好得多。
- 它的 `readme.md` 把系统分成四块：系统管理、党务工作中心（发展党员/党费/组织关系转接/表彰）、党群服务中心（走访联系/结对帮扶/志愿服务/党群活动）、教育培训中心（学习 + 考试）。

### 3.5 dangjian-sharon（GitHub ⭐21 / Apache-2.0）——**小程序 openid + 白名单**的最小样本

- 基于 Java 开源博客系统 **Halo** 改的「党建小程序」。
- `dangjian-halo/src/main/java/cc/ryanc/halo/model/domain/WxUser.java`：`@Table(name = "halo_wxUser")`，字段 `openId / nickName / sex / headUrl / province / city / createDate / lastLoginDate / ip`，并 **`@OneToOne` 关联 `White`（白名单）**。
- 意义：这正是「只有本支部党员能用」的落地方式（openid 入库 + 白名单准入），也是我们第二阶段上学校小程序时可以直接照抄的模型。

- **968626/Party-affairs-management**（⭐1）：仓库根目录只有 `README.md` + 7 张截图，**源码在 `mbd.pub` 付费链接里**，README 留微信号「jsjbyzd」——不是开源项目，是卖源码的引流仓库。
- **wwqking/Party-member-education-and-management-system**（⭐0，无许可证）：根目录 `pom.xml + src`（Spring Boot 单体），README 列了管理端（党费登记/奖惩/基础数据/基层单位/公告/党员/支部/支部日志/支部荣誉）+ 支部端；README 未提微信实现。
- **weixinapp1590**（⭐6，MIT）：uniapp 编译产物 `mp-weixin`，页面有 党建学习 / 支部动态 / 学习动态 / 知识分类 / 试卷 / 考试记录 / 收藏 / 讨论 + `login/register`；典型毕业设计结构，账号密码型。

## 4. 结论 A：这些做法**能用**（我建议搬进我们项目的）

1. **党务数据模型（来自 2473-CI，Apache-2.0，可放心参考）**：在现有 `Article/Activity/Enrollment/StudyRecord/LedgerFile/GalleryPhoto` 基础上，按需补 `党费 cost`、`组织关系转接 transfer`、`发展党员 expand`、`表彰 commend`、`结对帮扶 help`、`志愿服务 volunteer`、`谈话 Interview` 这几张表。表名和字段可自行命名，模型照它的思路走。
2. **小程序 openid + 白名单（来自 dangjian-sharon）**：`User` 表已有 `openid` 字段（现在显示「未绑定」），再加一张白名单/邀请表，就能做到「只有名单内的党员能进」。这是第二阶段最该先做的登录方式。
3. **微信参数存数据库、后台可填（来自 open-party）**：把 AppID/AppSecret/Token/AESKey 从 `.env` 挪到数据库 + 后台「微信设置」页。收益：① 本机 `.env` 被 CC Safety Net 锁死改不动的问题直接消失；② 第二阶段换学校公众号时，不用改代码、不用登服务器，后台改一下就行。
4. **公众号 OAuth 与小程序登录的调用位置（来自 open-party）**：`getWxCodeUrl()` → 回调拿 code → 后端换 openid。等学校号下来，我们的 `backend/wechat.py` 可以照这个补齐 `oauth2/authorize` 链接与回调路由。
5. **多公众号/多小程序配置 + Redis 存 token（来自 SmartPartyBuilding 的 `WxMpInRedisConfigStorage`）**：我们现在是「进程内缓存 access_token」，单机够用；将来多实例部署时再换成共享缓存即可——先把接口位置留出来。
6. **组织维度字段直接挂在用户/党员实体上（来自 万岳）**：我们已有 `Branch`，`User.branch_id` 就是这个思路，符合「先单支部、能扩多支部」的要求。
7. **大屏形态（来自 SmartPartyBuilding 的 dj-ui-go-view）**：我们的 `/dashboard` 已经是实时统计，后面可以再加一个「大屏模式」（纯展示、大字号、深色底），成本很低。
8. **毕业设计级项目的页面清单（来自 weixinapp1590）**：党建学习 / 支部动态 / 学习动态 / 知识分类 / 考试 / 收藏 / 讨论——可以挑「考试」「知识分类」作为后续可选功能。

## 5. 结论 B：这些做法**不能用**（说清楚为什么，以后不用再纠结）

1. **不能直接部署任何一个**：全部是 PHP（ThinkPHP/PhalApi + Redis）或 Java（SpringBoot/sofa-boot + MyBatis + Redis）多工程体系，要装 Java 8/11 + MySQL + Redis + Node 构建前端；我们的目标是 **Flask + SQLite、单机、一个人维护**，学校服务器上也希望尽量少装东西。功能可以补，栈不能换。
2. **不能抄代码**：open-party、万岳都是 **GPL-3.0** 且 README 另加「禁止倒卖/商用」；SmartPartyBuilding 是 **LGPL-3.0 + 必须标注四川民图**；zhipingsz 是 AGPL-3.0。**GPL/LGPL/AGPL 的代码整段抄进项目会传染许可证义务**，我们只参考思路和数据模型，不复制代码。可参考的是 2473-CI（Apache-2.0）和 dangjian-sharon（Apache-2.0）。
3. **不能靠它们解决「点菜单直接进系统」**：12 个项目里没有一个是用「个人未认证订阅号」做到的 —— open-party / SmartPartyBuilding 要求已认证服务号 + 已备案域名；dangjian-sharon / weixinapp1590 走的是小程序。**这和我们之前的实测结论完全一致**（个人号「跳转网页」保存必报「发布失败，链接内容不属于当前公众号」）。
4. **不能相信「开源版」的功能列表**：open-party 开源版没有三会一课/活动/台账/看板（商业版才有）；万岳 star 2616 但四块功能基本没实现；zhipingsz 连代码都没有；968626 是卖源码。**star 高 ≠ 能用**。
